# `rlib::derive_more_manual_constructors`

## Summary

Finds public constant `new` methods that only assign their parameters to every struct field.

## At a glance

| Field | Value |
| --- | --- |
| Group | `rlib::derive_more` |
| Cargo feature | `derive_more` |
| Purpose | API design |
| Default level | `warn` |
| Fix | Manual |

## What it catches

Finds public constant `new` methods that only assign their parameters to every struct field.

## Why this matters

A hand-written constructor obscures that construction has no validation, normalization, defaults, or
other policy and duplicates the interface generated by `derive_more::Constructor`.

## Examples

### Triggers the lint

```rust,ignore
impl Point {
    pub const fn new(x: i32, y: i32) -> Self { Self { x, y } }
}
```

### Use this instead

Declare the field-based constructor on the type.

```rust,ignore
#[derive(derive_more::Constructor)]
struct Point { x: i32, y: i32 }
```

## What it skips

No additional exclusions are documented.

## When to turn it off

Turn this lint off when the reported API is deliberate and callers depend on it.

This lint has no behavior-specific settings.
